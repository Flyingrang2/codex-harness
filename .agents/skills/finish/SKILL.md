# finish — 제출 전 마무리

## 하지 말 것
- 새 기능 추가·대규모 수정 (지금은 마무리 시간)
- 실제 코드와 다른 내용을 문서에 쓰기 — 문서와 코드가 대조된다
- 하지 않은 판단·검증 지어내기 — 근거를 못 찾으면 「미확인」으로 남긴다
- git commit (사용자가 한다)

## 순서
1. **필수 제출물**: README가 요구한 파일 목록 ↔ 실제 파일 대조 (있음 / 없음 / 비어 있음).
2. **여분 파일**: 사용자가 시키지 않은 파일 목록 → 지울지 물어보기(직접 지우지 않음).
3. **판단 문서**(README가 정한 이름, 없으면 DECISIONS.md): 판단마다 4칸이 있는지 점검하고 빈 칸만 채우기. 이유 칸은 사용자가 말한 이유 그대로.
   | 판단 | 근거(README·담당자 답 인용) | 검증 결과(명령·숫자) | 남은 한계 |
   각 줄이 실제 코드·결과와 일치하는지 파일:줄로 확인.
4. **남은 위험 3개**: ① 약점 지점(파일·기준) → ② 왜 위험한지 → ③ 다음에 무엇을 검증·개선할지.
5. **미완료 흔적**: TODO · TBD · 미완료 · placeholder 문구 검색 결과.
6. **1분 요약(화면에만, 파일 X)** — 사용자가 AI 없이 설명할 수 있게 쉬운 말로:
   - 전체 흐름 5줄: 무엇이 들어와서 → 어떤 기준으로 → 어떻게 처리돼 → 무엇이 나오고 → 어떻게 확인했나
   - 핵심 판단 3개: 「무엇을 / 왜(안 고른 방법도) / 어떻게 확인했나」 한 줄씩
   - AI가 틀렸던 순간 1~2개: NOTES.md 「AI가 틀린 순간」에서
