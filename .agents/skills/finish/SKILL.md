# finish — 제출 전 마무리

## 하지 말 것
- 새 기능을 넣거나 크게 고치지 마. 지금은 마무리할 때야.
- 실제 코드와 다른 말을 문서에 쓰지 마. 문서와 코드를 대조해 볼 거야.
- 안 한 판단이나 검증을 지어내지 마. 근거를 못 찾으면 「미확인」으로 남겨.
- git commit은 사용자가 「커밋해」라고 할 때만 해.

## 순서
1. **필수 제출물**: README가 요구한 파일과 실제 파일을 대조해. 각각 있는지, 없는지, 비어 있는지 표시해.
2. **여분 파일**: 사용자가 시키지 않은 파일을 찾아서 지울지 물어봐. 네가 바로 지우지는 마.
3. **판단 문서**: README가 정한 이름(없으면 DECISIONS.md)을 열어. 판단마다 아래 4칸이 다 있는지 보고 빈칸만 채워. 이유(근거) 칸은 사용자가 말한 그대로 적어.
   | 판단 | 근거(README·담당자 답 인용) | 검증 결과(명령·숫자) | 남은 한계 |
   각 줄이 실제 코드·결과와 맞는지 파일 이름과 줄 번호로 확인해.
4. **남은 위험 3개**: ① 어디가 약한지(파일·기준) → ② 왜 위험한지 → ③ 다음에 무엇을 확인하고 고칠지 순서대로 적어.
5. **미완료 흔적**: TODO, TBD, 미완료, placeholder 같은 문구가 남아 있는지 찾아서 보여줘.
6. **1분 요약**: 파일로 만들지 말고 화면에만 띄워. 사용자가 AI 없이도 직접 설명할 수 있게 쉬운 말로 써.
   - 전체 흐름 5줄: 무엇이 들어와서 → 어떤 기준으로 → 어떻게 처리돼 → 무엇이 나오고 → 어떻게 확인했나
   - 핵심 판단 3개: 「무엇을 / 왜(안 고른 방법도) / 어떻게 확인했나」를 한 줄씩
   - AI 오답 1~2개: NOTES.md의 「## AI 오답노트」에서 골라 「무엇이 틀렸고 → 어떻게 알아챘고 → 어떻게 고쳤나」
