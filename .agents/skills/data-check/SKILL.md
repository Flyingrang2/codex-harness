# data-check — 고치기 전에, 믿을 만한지부터

데이터를 분석하거나 고치기 전에 함정이 몇 개인지 **숫자로** 세서 보고해. 어떻게 처리할지는 사용자가 정해.

## 하지 말 것
- 데이터 파일을 고치거나 지우지 마. 어떻게 처리할지도 혼자 정하지 마.
- 파일 전체를 화면에 띄우지 마. 앞 5줄과 개수 요약만 보여 줘.
- 점검용 파일을 따로 만들지 마. 터미널에서 `python -c`나 `node -e` 같은 일회성 명령으로만 확인해.

## 명심
- 0이나 음수, TEST 표시는 **의심 신호일 뿐이지 무조건 빼야 하는 게 아니야.** 빼거나 고칠지는 README나 담당자 기준을 보고 사용자가 정해.
- 개수를 셀 때는 항상 코드로 전체 행을 끝까지 다 세. 앞 5줄은 모양만 보는 용도야.
- 1~2단계로 먼저 빠르게 훑고, 핵심 숫자가 바뀔 만한 곳만 깊게 파. 넘어간 항목은 「안 봄 + 이유」라고 적어.

## 순서
1. **개요**: 파일 목록, 크기, 행 수, 열 이름, 앞 5줄을 확인해.
2. **열마다**: 빈 값과 고유값이 각각 몇 개인지 세. 값이 몇 종류로 나뉘는 열이면 값별 개수를 상위 10개까지 뽑아.
3. **의심 체크** — 아래에 걸리면 행 수와 예시 3개를 뽑아:
   - 중복: 완전히 똑같은 행 / ID+시각처럼 같은 키가 여러 번 나오는 행
   - 시간: Z, +09:00, 표기 없음처럼 시간대 표기가 섞여 있음 · 월말·자정·교대 시각 같은 기간 경계에 걸침 · 시작이 끝보다 늦음 · 진행 중이라 끝 시각이 비어 있음 · 구간이 겹침
   - 숫자: 0 · 음수 · 너무 크거나 작은 값 · 분/초, %/비율, 원/천원처럼 단위가 섞여 있음
   - ID·이름: 대소문자나 띄어쓰기가 다름 · 별칭이나 바뀐 이름 · 폐기됐거나 안 쓰는 대상 · TEST/DUMMY/샘플 행
   - 상태값: 취소·재시도·재검사·예외 상태 · 철자가 조금씩 다름
   - 연결: 다른 파일과 키가 안 맞는 행 · 부분합과 전체합이 다름
4. **보고**: 표 하나로 10줄 안에 정리해.

|---|---|---|---|---|

5. 끝에 한 줄 덧붙여: 「처리 기준이 필요한 것 N개 — 정해 주면 판단 문서에 적고 진행할게.」
