# data-check — 고치기 전에, 믿을 만한지부터

목적: 분석·수정 전에 데이터의 함정을 **숫자로** 찾아 사용자에게 보고한다. 처리 기준은 사용자가 정한다.

## 하지 말 것
- 데이터 파일 수정·삭제, 처리 기준 혼자 정하기
- 파일 전체를 화면에 출력하기 (앞 5줄 + 개수 요약만)
- 점검용 파일 만들기 → 일회용 터미널 명령(python -c, node -e 등)으로만

## 명심
- 0·음수·TEST 표시 같은 건 **의심 신호일 뿐 제외 근거가 아니다.** 빼거나 고칠지는 README·담당자 기준과 사용자가 정한다.
- 먼저 빠르게 훑고(1~2단계), 핵심 숫자에 영향을 줄 의심 지점만 깊게 판다. 안 본 항목은 「안 봄 + 이유」로 적는다.

## 순서
1. **개요**: 파일 목록 · 크기 · 행 수 · 열 이름 · 앞 5줄.
2. **열마다**: 빈 값 수 · 고유값 수 · 범주형이면 값별 개수(상위 10).
3. **의심 체크** — 걸리면 행 수와 예시 3개:
   - 중복: 완전히 같은 행 / 같은 키(ID+시각 등) 여러 번
   - 시간: 시간대 표기 섞임(Z, +09:00, 표기 없음) · 기간 경계(월말·자정·교대 시각) · 시작 > 끝 · 끝이 비어 있음(진행 중) · 구간 겹침
   - 숫자: 0 · 음수 · 극단값 · 단위 섞임(분/초, %/비율, 원/천원)
   - ID·이름: 대소문자·공백 차이 · 별칭·이름 변경 · 폐기·비활성 대상 · TEST/DUMMY/샘플 행
   - 상태값: 취소·재시도·재검사·예외 상태 · 철자 변형
   - 연결: 다른 파일과 키가 안 맞는 행 · 부분합 ≠ 전체합
4. **보고** (표 하나, 10줄 이내):

| 문제 | 행 수 | 예시 | 결과에 주는 영향 | 결정 필요? (담당자에게 물을 것) |
|---|---|---|---|---|

5. 끝에 한 줄: 「처리 기준이 필요한 것 N개 — 정해 주면 DECISIONS.md에 적고 진행할게.」
