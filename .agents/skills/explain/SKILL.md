# explain — 내가 설명할 수 있어야 내 결과물이다

## 하지 말 것
- 길게 설명하지 마. 1~6단계를 다 합쳐서 15줄 안에 끝내.
- 사용자가 말하지 않은 이유를 지어내지 마. 근거가 없으면 「근거 없음」이라고 써.
- 사용자 대신 NOTES.md에 설명을 적어 주지 마.

## 순서
1. **무엇을 바꿨나**: 바꾼 파일과 함수 이름에 한 줄 설명을 붙여.
2. **왜**: 근거를 한 줄로 대. README 몇 번째 줄인지, 담당자 답인지, 사용자가 정한 건지 밝혀.
3. **전후 숫자**: 핵심 숫자 1~2개가 어떻게 바뀌었는지 보여 줘.
4. **안 고른 방법**: 다른 방법 1개와 그걸 안 고른 이유를 대.
5. **깨지는 경우**: 이 결과가 틀릴 수 있는 입력이나 상황 1개를 짚고, 다음에 무엇을 확인하면 되는지 알려 줘.
6. **질문 1개**: 「이걸 왜 이렇게 했나요?」 같은 질문을 하나 던지고, **답은 쓰지 말고 기다려.**
7. 사용자가 답하면 **틀린 부분만** 짚어 줘. 맞으면 「맞아」 한마디면 돼. 그다음 사용자가 직접 NOTES.md에 자기 말로 2줄 적게 해.
7-1. 이번 단계에서 **네가 처음에 틀렸다가 고친 것**이 있으면 사실대로 한 줄로 말해. 무엇이 틀렸고, 어떻게 알아챘고, 어떻게 고쳤는지 써. 이건 사용자가 NOTES.md 「## AI 오답노트」에 적을 거야.
8. `/status`에서 대화량이 많아졌거나 한 단계가 끝났으면, NOTES.md의 「## 인계」 칸을 10줄 이내로 고쳐 써. 확정 기준, 한 일, 검증된 숫자, 남은 일, 주의점을 담아. 사용자가 확인하면 `/new`로 새 대화를 열고 「NOTES.md 인계 읽고 이어가」라고 쳐서 다시 시작하게 해.
