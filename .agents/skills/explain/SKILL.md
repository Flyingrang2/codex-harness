# explain — 내가 설명할 수 있어야 내 결과물이다

## 하지 말 것
- 긴 설명 (1~6단계 합쳐 15줄 이내)
- 사용자가 말하지 않은 이유 지어내기 — 근거가 없으면 「근거 없음」이라고 쓴다
- 사용자 대신 NOTES.md에 설명을 써 주기

## 순서
1. **무엇을 바꿨나**: 파일·함수 이름 + 한 줄.
2. **왜**: 근거 한 줄 — README 몇 줄인지 / 담당자 답인지 / 사용자 결정인지 밝힌다.
3. **전후 숫자**: 핵심 숫자 1~2개가 어떻게 바뀌었나.
4. **안 고른 방법**: 다른 선택지 1개와 안 고른 이유.
5. **깨지는 경우**: 이 결과가 틀릴 수 있는 입력·상황 1개 → 다음에 무엇을 확인하면 되나.
6. **질문 1개**: 「이걸 왜 이렇게 했나요?」 같은 질문을 하나 던지고, **답은 쓰지 말고 기다린다.**
7. 사용자가 답하면 **틀린 부분만** 짚는다(맞으면 「맞아」 한마디). 그다음 사용자가 NOTES.md에 자기 말로 2줄 적게 한다.
7-1. 이번 단계에서 **내가(AI) 틀렸다가 고쳐진 것**이 있으면 사실대로 한 줄: 무엇이 틀렸고 어떻게 알았나. 사용자가 NOTES.md 「## AI가 틀린 순간」에 적는다.
8. (`/status` 컨텍스트가 크거나 단계가 끝났으면) NOTES.md 「## 인계」 칸을 10줄 이내로 고친다: 확정 기준 / 한 일 / 검증된 숫자 / 남은 일 / 주의점. 사용자가 확인하면 `/new` 후 「NOTES.md 인계 읽고 이어가」로 다시 시작한다.
