# verify — 「완료」 메시지 ≠ 완료

목적: 사용자가 눈으로 확인할 수 있는 증거를 만든다. 틀린 게 보이면 **고치지 말고 먼저 보고**한다.

## 하지 말 것
- 테스트 기대값을 바꿔서 통과시키기
- 출력 형식(필드 이름·타입·순서) 바꾸기
- 검증 결과를 좋게 요약하기 — 실패는 실패라고 쓴다
- 없는 숫자 만들기 — 고치기 전 값을 안 재 뒀으면 「기록에 없음」이라고 쓴다

## 순서
0. **고치기 전 기준값**: 수정 전이라면 지금 실행 명령·결과·핵심 숫자를 먼저 기록해 둔다.
1. **전후 비교**: 같은 명령을 고치기 전/후로 돌린 핵심 숫자 표(바뀐 칸만 표시). 데이터 처리 기준(유지·제외·보정·보류)마다 해당 건수와 처리 전후 행 수. 여러 기준에 겹치는 행은 겹친다고 밝힌다.
2. **독립 재계산**: 핵심 숫자 1~2개를 **원본 행부터 다른 방법**(다른 코드 경로·짧은 일회용 명령·손계산 가능한 작은 표본)으로 다시 계산해 일치하는지.
3. **경계·반례 3개**: 빈 입력 · 경계값(기간 끝·0·동점) · 제외하기로 한 행이 정말 빠졌는지.
4. **요구사항 대조**: README·담당자 기준 항목별 ✅/❌ + 근거(파일:줄 또는 실행 결과).
5. **테스트**: 실행 명령과 결과를 그대로(통과 수/실패 수).
6. **형식**: 출력 파일·API 응답의 필드가 원래 요구대로인지.
7. **검산 남기기**: 2단계에서 확인한 핵심 숫자를 테스트 1개로 남겨(새 파일이면 허락받고) 다음 단계마다 다시 돌린다 — 같은 실수가 다시 들어오면 바로 잡힌다.

## 보고
- 맨 위 한 줄: 「검증 통과」 또는 「문제 N개 발견」.
- 문제마다: 무엇이 · 어떻게 알았나(명령·숫자) · 영향 · 고칠 방법 제안(아직 안 고침).
