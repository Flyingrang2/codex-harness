# 검증 — 「됐다」는 말 대신 증거를 보여라

맨 첫 줄에 판정 결과를 적어라: 검증 통과 / 문제 N개

1. 규칙 대조: README 규칙 목록(notes/EXPLAIN.md)과 notes/QA.md의 기준을 하나씩 대조해 표로 보여 줘라 — 규칙 · 지켰나(✅/❌) · 근거(파일:줄 또는 실행 결과)
2. 다른 방법으로 재계산: 핵심 숫자 1~2개를 골라 본 코드와 다른 방식(다른 명령어를 쓰거나, ID 하나를 골라 원본 행을 직접 더하는 등)으로 다시 계산하고 「본 코드 vs 재계산」 결과를 나란히 보여 줘라. 이때 재계산은 계산 과정이 맞는지만 보여 줄 뿐, 무엇을 넣고 뺄지 정한 기준 자체가 맞는지는 증명하지 못한다는 점도 함께 밝혀라.
3. 경계 사례 확인: 빈칸 · 0·음수·튀는 값 · 기간 양 끝(이상/초과) · 동점이 데이터에 있다면 실제로 어떻게 처리됐는지 사례를 1건씩 보여 줘라. 해당 데이터가 없으면 「해당 데이터 없음」이라고 적어라.
4. 테스트 결과: 실행한 테스트 명령과 통과/실패 개수를 그대로 보여 줘라. 테스트를 통과시키려고 정답(기대값)을 바꾸지 마라.
5. 제출 전 점검: README가 요구한 파일이 모두 있는지, 형식(열 이름·순서·소수점)이 맞는지 ✅/❌로 표시해라. 내가 시키지 않은 파일이 있으면 목록만 보여 주고 지울지 물어봐라.

문제가 발견되면 혼자 고치지 말고 먼저 보고해라. 네가 짠 코드나 네가 처음 세운 가정 때문에 틀렸다면 무엇이 왜 틀렸는지 솔직하게 말해라.
