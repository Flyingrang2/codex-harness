# 검증 — 「됐다」는 말 대신 증거를 보여라

결과는 notes/VERIFY.md에 적어라. 파일이 이미 있으면 지우지 말고 맨 아래에 [시각] 제목으로 덧붙여라. 화면에는 판정 결과와 ❌ 항목을 먼저 보여 줘라.

첫 줄: 검증 통과 / 문제 N개

1. README 규칙 대조: README를 직접 다시 읽고 반올림·형식·포함/제외·정렬·단위 등 적힌 규칙을 빠짐없이 뽑아라. 규칙마다 한 줄로 적어라 — ✅/❌ 규칙(README:줄) → 근거(파일:줄 또는 실행 결과)
2. 확정 기준 대조: notes/ISSUES.md의 「확정」 카드와 notes/QA.md 기준마다 한 줄로 적어라 — ✅/❌ I-번호 기준 → 코드 위치(파일:줄) → 실제 행 하나가 그 기준대로 처리된 증거. 아직 「미확인」인 카드가 있으면 따로 적어라.
3. 다른 방법으로 재계산: 핵심 숫자 1~2개를 본 코드와 다른 방식(다른 명령어, 하나를 골라 원본 행을 직접 더하기 등)으로 다시 계산하고 「본 코드 vs 재계산」을 나란히 보여 줘라. 더한 원본 행도 함께 보여 줘서 내가 손으로 따라 할 수 있게 해라. 재계산은 계산 과정이 맞는지만 보여 줄 뿐, 무엇을 넣고 뺄지 정한 기준 자체가 맞는지는 증명하지 못한다는 점도 밝혀라.
4. 경계 사례: 빈칸 · 0·음수·튀는 값 · 기간 양 끝(이상/초과) · 동점이 데이터에 있으면 실제로 어떻게 처리됐는지 1건씩 보여 줘라. 없으면 「해당 데이터 없음」이라고 적어라.
5. 테스트: 실행한 테스트 명령과 통과/실패 개수를 그대로 보여 줘라. 테스트를 통과시키려고 정답(기대값)을 바꾸지 마라.
6. 다시 실행: 결과 파일을 만드는 명령을 한 번 더 실행해 같은 결과가 나오는지 확인해라.
7. 제출 전 점검: README가 요구한 파일이 모두 있는지, 형식(열 이름·순서·소수점)이 맞는지 ✅/❌로 표시해라. 내가 시키지 않은 파일이 있으면 목록만 보여 주고 지울지 물어봐라. 내 작업 도구(AGENTS.md·harness-skills/·notes/)는 이 목록에서 뺀다.

문제가 발견되면 혼자 고치지 말고 먼저 보고해라. 네가 짠 코드나 네가 처음 세운 가정 때문에 틀렸다면 무엇이 왜 틀렸는지 솔직하게 말해라.

검증도 앞선 대화를 모르는 새 Codex 세션에서 하면 더 독립적이다. 이번 대화 안에서 네가 결과를 만드는 코드를 짰거나 고쳤다면 첫 줄 끝에 「같은 세션」이라고 적어라.
